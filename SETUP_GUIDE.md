# GitHub Project Setup Guide

This repository's issues and planning files are prepared for the Assignment-5 workflow.

## 1. Create the GitHub Project
1. Open this repository and choose **Projects**.
2. Select **New project** and choose **Table**.
3. Name it **Online Food Ordering - Scrum Project**.

## 2. Add custom fields
Create:
- **Priority** — Single select: High, Medium, Low
- **Story Points** — Number

Set the fields on the five user-story issues/items as follows:
| User story | Priority | Story Points |
|---|---|---:|
| Customer Login | High | 3 |
| Browse Restaurants and Menu | High | 5 |
| Shopping Cart | High | 5 |
| Online Payment | High | 8 |
| Order Tracking | Medium | 5 |

## 3. Product Backlog and Sprint 1
Add the five US issues to the project table. Sprint 1 goal: **Allow customers to log in, browse the menu, and add food items to the cart.**
Sprint 1 stories: US01, US02, US03. Keep US04 and US05 in the Product Backlog for now.

## 4. Create the Sprint Board
Create a second view, choose **Board**, and name it **Sprint Board**. Configure Status columns:
- Todo
- In Progress
- Testing
- Done

If Testing is not an available Status option, edit the Status field options to add it.

## 5. Sprint tasks
Task issues are created in this repository and named with the user story they belong to. Add them to the project and set their status as work progresses. Use the labels/titles to identify Sprint 1 vs Sprint 2.

## 6. Scrum events
Use the examples in [SCRUM_EVENTS.md](SCRUM_EVENTS.md) for Daily Scrum, Sprint Review, and Retrospective.

## Final checklist
- [ ] Project named Online Food Ordering - Scrum Project
- [ ] Five user-story issues added to Product Backlog
- [ ] Priority and Story Points fields configured
- [ ] Sprint 1 includes US01, US02, US03 and their tasks
- [ ] Sprint Board includes Todo, In Progress, Testing, Done
- [ ] Daily Scrum example recorded
- [ ] Sprint Review increment demonstrated
- [ ] Retrospective responses recorded
- [ ] Sprint 2 includes Online Payment and Order Tracking tasks

Note: The GitHub Project board and its custom fields must be configured in GitHub's Projects interface. The issue tracker and documentation are being set up here directly.
